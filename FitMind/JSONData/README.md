# Данные FitMind в формате JSON

При первом запуске `JsonDatabaseSeeder` заполняет пустую базу SQL Server данными из этих файлов.

## Файлы

- `seed-manifest.json` — основной manifest загрузки. Он перечисляет каждую таблицу и её JSON-файл.
- `tables/*.json` — **66 отдельных файлов, по одному на таблицу**. Формат каждого: `table` и массив `rows`.
- `database-seed.json` — прежний единый снимок. Он сохранён временно как совместимый fallback для старых сборок, но текущий сайт сначала использует `seed-manifest.json` и файлы из `tables/`.
- `catalog.json` — исходные импортированные наборы, источники, формулы, связи и справочные материалы. Он сохранён для просмотра исходного наполнения.

В начальном наборе содержатся, в частности, упражнения, готовые программы и этапы, добавки, материалы базы знаний, восстановление, замеры, калькуляторы, продукты, рецепты, справочники и связанная информация. Записи пользователей создаются через ASP.NET Identity отдельно.

## Изображения

У каталогов с карточками каждая запись содержит столбец `Изображение` с путём
вида `/images/...`. Сам файл хранится в `wwwroot/images/`, то есть вместе с
проектом и доступен браузеру. Перед импортом загрузчик проверяет, что каждый
такой путь ведёт к существующему локальному файлу; при ошибке импорт отменяется.
Бинарные файлы не дублируются в SQLite или JSON: они являются статическими
ресурсами приложения, а значение `Изображение` — частью данных конкретной записи.

Загруженные аватары не относятся к стартовому наполнению. После проверки формата
и размера они автоматически сохраняются в `App_Data/avatars` и выдаются только
через endpoint профиля текущего пользователя.

## Обновление начального набора

Изменяйте нужный файл в `tables/`, сохраняя название таблицы и её столбцов. Связанные записи должны иметь существующие ID; например, день программы нельзя добавить раньше самой программы, а упражнение дня — раньше упражнения и дня. Порядок импорта указан в `seed-manifest.json`.

Загрузчик проверяет, что таблицы и столбцы из JSON существуют в модели SQLite. Если схема отличается или в данных нарушены связи, приложение остановит импорт с сообщением об ошибке вместо молчаливого пропуска.

Новые JSON применяются только при заполнении новой пустой базы. Для проверки указывайте отдельное имя через `Database__FileName`, например `fitmind-json-test.db`; не удаляйте и не пересоздавайте рабочую `App_Data/fitmind.db`.

Файлы Identity и личных записей созданы пустыми намеренно: пользователей, пароли, токены, дневники и аватары нельзя добавлять в тестовое начальное наполнение.
