# FitMind

FitMind — веб-приложение для комплексного контроля тренировок, питания, сна, восстановления и личного прогресса.

Приложение объединяет основные инструменты для ведения здорового образа жизни: пользователь может составлять программы, планировать занятия, вести дневники, сохранять показатели и отслеживать изменения.

## Демо

Приложение опубликовано по адресу:

[https://fitmind.runasp.net](https://fitmind.runasp.net)

- планирование занятий;

- сохранение результатов;
- ведение истории тренировок.

### Питание

- просмотр пищевой ценности;

- создание личного плана питания;
- добавление приёмов пищи;
- ведение дневника питания;
- просмотр истории записей.

### Сон и восстановление

- готовые программы сна;
- рекомендации по восстановлению;
- создание личных планов;

- ведение истории восстановления.

### Добавки

- создание личного плана приёма;
- редактирование расписания;

### Отслеживание прогресса

- добавление измерений тела;

## Административная панель

Для пользователей с ролью администратора предусмотрена отдельная панель управления.

Администратор может:

- управлять пользователями;
- работать со справочниками;
- создавать и изменять программы тренировок;
- управлять программами питания и сна;
- добавлять упражнения;
- редактировать продукты и рецепты;
- управлять материалами о восстановлении;
- добавлять информацию о спортивных добавках;
- публиковать статьи;
- загружать изображения;
- управлять видимостью контента.

## Панели управления базой данных

Административная часть FitMind содержит отдельные панели для просмотра и редактирования содержимого базы данных.

Изменения, выполненные через эти панели, сохраняются в Microsoft SQL Server и используются пользовательской частью приложения.

### Обзор

Главная страница административной панели показывает общее состояние системы и предоставляет быстрый переход к основным разделам управления.

### Пользователи

Панель предназначена для управления зарегистрированными аккаунтами.

Администратор может:

- просматривать список пользователей;
- находить пользователя по электронной почте;
- просматривать основную информацию об аккаунте;
- назначать административную роль;
- снимать административную роль;
- контролировать состояние учётных записей.

Пароли пользователей не хранятся в открытом виде и не отображаются администратору.

### Справочники

В этом разделе находятся общие значения, используемые другими частями приложения.

Справочники позволяют централизованно управлять:

- категориями;
- типами;
- уровнями сложности;
- целями;
- единицами измерения;
- другими повторно используемыми значениями.

### Программы тренировок

- название;

- целевую аудиторию;

- изображение;
- статус публикации.

## Пользовательские данные в базе

Помимо административного контента, база данных хранит личные записи пользователей:

- профиль и настройки аккаунта;
- цели и тренировочные предпочтения;
- личные программы тренировок;
- тренировочные дни;
- персональное расписание;
- историю выполненных тренировок;
- дневник питания;
- личные продукты и рецепты;
- планы сна;
- записи о восстановлении;
- планы приёма добавок;
- измерения тела;
- уведомления.

Пользовательские записи привязаны к владельцу аккаунта. Один пользователь не должен получать доступ к личным данным другого пользователя.

## Связи между разделами

Основные сущности базы данных связаны между собой:

- программа тренировок содержит тренировочные дни;
- тренировочный день содержит упражнения;
- пользователь может добавить готовую программу в личный профиль;
- продукты и рецепты используются в дневнике питания;
- способы восстановления используются в личных планах;
- добавки включаются в пользовательское расписание приёма;
- измерения и выполненные тренировки используются для отслеживания прогресса.

Удаление связанных записей контролируется приложением, чтобы не оставлять повреждённые или потерянные данные.

## Работа с изображениями

Для программ, упражнений, продуктов, рецептов, добавок, материалов восстановления и статей можно загружать изображения.

В базе данных сохраняется информация о прикреплённом изображении, а приложение отображает его в пользовательской и административной частях.

Если изображение отсутствует, используется тематическая заглушка.

## Публикация контента

Большинство административных записей имеют статус публикации.

Это позволяет:

- сохранить незавершённую запись как черновик;
- проверить информацию перед публикацией;
- временно скрыть материал;
- показывать пользователям только готовый контент.

Изменение статуса публикации не удаляет запись из базы данных.

## Архитектура проекта

Проект построен по архитектуре MVC:

- `Controllers` — обработка запросов и взаимодействие между моделями и страницами;
- `Models` — основные модели данных;
- `ViewModels` — модели представления;
- `Views` — Razor-страницы пользовательского интерфейса;
- `Data` — контекст базы данных и первоначальное заполнение;
- `Migrations` — миграции Entity Framework Core;
- `Services` — почта, изображения и прикладные сервисы;
- `Areas/Admin` — административная панель;
- `wwwroot` — CSS, JavaScript, изображения и другие статические файлы;
- `JSONData` — данные для первоначального заполнения базы.

```bash
dotnet run --project FitMind/FitMind.csproj
```

После запуска адрес приложения будет указан в консоли.

При первом запуске приложение создаёт структуру базы данных и добавляет начальные данные.

## Подключение к базе данных

По умолчанию для локальной разработки используется SQL Server LocalDB.

Строка подключения находится в `appsettings.json`:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=(localdb)\\MSSQLLocalDB;Database=FitMind;Trusted_Connection=True;MultipleActiveResultSets=true;TrustServerCertificate=True"
  }
}
```

Для опубликованной версии необходимо использовать отдельную серверную базу данных.

Производственные пароли и строки подключения не должны сохраняться в репозитории.

## Миграции базы данных

Для создания или обновления базы данных используются миграции Entity Framework Core.

Применение миграций:

```bash
dotnet ef database update --project FitMind/FitMind.csproj
```

Создание новой миграции:

```bash
dotnet ef migrations add MigrationName --project FitMind/FitMind.csproj
```

Перед изменением рабочей базы рекомендуется создавать резервную копию.

## Настройка входа через Google

Для работы Google OAuth необходимо создать OAuth-клиент типа «Веб-приложение» в Google Cloud Console.

Локальные секреты сохраняются через User Secrets:

```bash
dotnet user-secrets set "Authentication:Google:ClientId" "YOUR_GOOGLE_CLIENT_ID" --project FitMind/FitMind.csproj
dotnet user-secrets set "Authentication:Google:ClientSecret" "YOUR_GOOGLE_CLIENT_SECRET" --project FitMind/FitMind.csproj
```

Для локального запуска в Google Cloud Console необходимо добавить URI перенаправления, например:

```text
https://localhost:7182/signin-google
```

Для опубликованной версии FitMind используется:

```text
https://fitmind.runasp.net/signin-google
```

Авторизованный источник JavaScript опубликованной версии:

```text
https://fitmind.runasp.net
```

## Настройка восстановления пароля

Для отправки писем используется Resend API.

API-ключ сохраняется через User Secrets:

```bash
dotnet user-secrets set "Email:Provider" "Resend" --project FitMind/FitMind.csproj
dotnet user-secrets set "Email:Resend:ApiKey" "YOUR_RESEND_API_KEY" --project FitMind/FitMind.csproj
```

В `appsettings.json` нельзя добавлять настоящий API-ключ.

Для отправки писем любым пользователям в Resend необходимо подключить и подтвердить собственный домен отправителя.

## Публикация

Проект может быть опубликован на хостинге с поддержкой ASP.NET Core 8 и Microsoft SQL Server.

Текущая версия размещена на MonsterASP.NET:

```text
https://fitmind.runasp.net
```

Для публикации необходимо:

1. создать веб-сайт;
2. создать базу Microsoft SQL Server;
3. применить миграции или восстановить резервную копию;
4. указать серверную строку подключения;
5. добавить секреты Google OAuth;
6. добавить ключ почтового сервиса;
7. выполнить Release-публикацию приложения;
8. загрузить опубликованные файлы в `wwwroot`;
9. подключить HTTPS-сертификат;
10. настроить URI перенаправления в Google Cloud Console.

GitHub хранит исходный код проекта, но не выполняет автоматическую публикацию на MonsterASP.NET.
